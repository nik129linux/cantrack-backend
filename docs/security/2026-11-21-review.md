# CanTrack local security and runtime review

Historical snapshot: the corrections described here are included in the 2026-11-24
source delivery. References to uncommitted local work describe the original review date.
Current validation is recorded in `../VERIFICATION.md`; production was not redeployed.

Date: 2026-11-21. Changes are local, uncommitted, and not deployed.

## Scope

Backend: `CanTrack-backend/apps/api-py`. Frontend: sibling `CanTrack/apps/web`.
The user clarified that the required stack is Python for the backend and TypeScript
for the frontend. Both requirements are satisfied; no language migration is needed.
The backend application source contains 63 Python files. Frontend source contains
19 TypeScript files, 55 TSX files, and 25 CSS files, with no JavaScript source files.
The API entrypoint and Docker image execute Python; the web entrypoint is `main.tsx`.

## Corrections

1. Anonymous authentication endpoints previously derived their rate-limit key from
   any supplied bearer string, without verifying it. Rotating fabricated strings
   bypassed login, reset-password, and verification limits in three regression tests.
   Signup, login, reset-password, resend-verification, and refresh now use the client
   IP key. Explicitly configured proxy headers retain their existing trust semantics.
2. Updated vulnerable dependencies and the reproducible `uv.lock`: FastAPI, Starlette,
   Pillow, certifi, dnspython, filelock, OpenTelemetry API, and pytest. Migrated the fuzz
   test's loader and transport to Schemathesis 4, preserving its assertions, both
   caller roles, and the configured Hypothesis example count. Removed the OpenAPI
   3.0 downgrade; the tests now read the application's native OpenAPI 3.1 schema.
3. Demo credentials now receive a protected owner-only Windows ACL before any secret
   is written. POSIX permissions are also applied before writing an existing file.
   Tests verify new files, existing files, and refusal to write when permissions fail.

## Remaining limitations and requirements

- The verified application stack is Python/FastAPI for the backend and
  TypeScript/React for the frontend, as clarified by the user. No migration is pending.
- Backend identifiers and most comments/errors use English, but navigation text,
  some docstrings, and demo content still contain Spanish. The English-only backend
  requirement is not satisfied. Proper names and user data should remain intact.
- These local corrections are not present in the AWS deployment. Its successful
  smoke test does not establish that it has the updated dependencies or fixes.
- Browser coverage was limited to the existing demo walker account and read flows;
  it does not establish complete end-to-end behavior for both roles or all writes.
- Five tests were skipped; they are not counted as passed.
- Starlette warns that its TestClient's httpx compatibility will be removed in favor
  of httpx2. Current tests pass with httpx; this remains a future compatibility task.
- Vite reports a JavaScript chunk larger than 500 kB; performance optimization remains.
- Rate-limit state remains per process/in memory. Distributed enforcement and proxy
  configuration need verification if the deployment scales beyond one process.
- No production database migration, cloud deployment, or existing credentials-file
  rewrite was performed. Private AI dependencies require a separate source audit.
